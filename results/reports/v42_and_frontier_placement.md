## 一、v42（v41 + BUYDIP）—— **不通过，拒绝**

| | block A (1000-1049) | block B (4000-4049) | 合计 800 局 |
|---|---|---|---|
| v41（对照） | **87.2%** | 86.0% | 86.6% |
| **v42（+`_BD`）** | **86.2%** | **86.5%** | 86.4% |
| 对 tetsutani_cha22 | 56% → **52%** | 54% → **56%** | —— |
| **最差单局** | −$3,309 → **−$10,316** | −$4,148 → **−$8,060** | —— |

**否决依据（两条，都不是"差一点"）：**

1. **两块种子方向相反**（A 退化 1.0pp、B 改善 0.5pp）→ 按 L3 纪律，两块必须同向。
2. **尾部风险在两块都显著恶化**：最差单局翻倍以上。总量持平是用"多数局微增"掩盖了"少数局灾难"。

**机制假说**：`_BD` 在现价高于 12 步均价时扣下最多一半的大额小麦买单（上限 64 单位），
但**释放速率只有每回合 `min(pending, 8)`** → 64 单位要 8 回合放完。
"计划中的买入被扣下"正是我们 M1 早死 bug 的同一失败类别。

**方法学意义**：阶梯里 `_BD` 值 −8pp 是**对 tetsutani 的栈**测的。
层与层、层与底座不独立 → **必须叠到自己身上、且两块同向才算数**。

## 二、前线定位：**我们在"最强公开 agent"之上**

### 2.1 先确认了一件事实：我们的 `main.py` 是 ahmed v56 的严格超集

用 `scripts/token_compare.py` 做标识符级 diff（**不是**整体相似度——见 L13）：

| 方向 | 数量 | 内容 |
|---|---|---|
| 只有 v56 有 | **1 个** | `b64decode`（它内嵌 payload 的解码器，不是策略代码） |
| 只有我们有 | **123 个** | `_33_*`、`_ADV_*`、`_ER_*`、`_FRO_*`、`_HR_*`、`_IG_*`、`_R148_*`、`_VQ_*` … |

并且 **`e410_agent`（v56 的 Kaggle 入口）与 `e402_agent` 在我们的文件里与 v56 的逐字节相同**
（2,155 / 1,878 字符，AST 提取后 assert 相等）。

⇒ **我们的 agent = v56 全栈 + 我们自己约 20 层。** 所以"我们 vs v56"测的是
**我们自己加料的净价值**，基准完全相同——这是本地能做到的最干净的对照。

### 2.2 结果（两块独立种子，各 200 局）

**两块同向；v41 > v37 在两块都成立。**

### 2.3 这条结论推翻了一个我们一直默认的前提

| 旧默认 | 新事实 |
|---|---|
| "我们是一个强公开 agent 的近乎逐字克隆"（README / 多份 sources） | ✅ 克隆部分成立（`e410_agent` 逐字节相同），**但我们在此之上加了 123 个符号的层**，而它们值 **+89pp**（对 v56） |
| "pipe18 说 ahmed v56 是最强公开 agent，我们本地只有 v55" | 我们**已经包含 v56**，并且**赢它 89–96%** |

**唯一能压我们的是 `tetsutani_cha22`**（我们 55%），而它正是同一底盘 + 另一套层
（cha20 链 + `_CXD`）。v40/v41 已经把这个差距从 22% 拉到 55%。

## 三、收尾规则（写进巡检 cron）

窗口 = 2，取 **max**。当前：

```
ref 56537565   v40   PENDING      ← 挑战者
ref 56524969   v36   2348.x       ← 锚
（v37 ref 56521206 = 2289.2，已被挤出）
```

**规则：等 v40 出分后再提交 v41 到【较弱的那一格】。**

- 若 v40 ≥ 2348 → v40 成为新锚，用 v41 替换 v36 那一格；
- 若 v40 < 2348 → v41 替换 v40 那一格（我们只丢一个更弱的候选）。

**两种情况下提交 v41 都是"弱优势"动作**，因为替换掉的总是较低分的一格。
**在此之前不要提交**——现在提交会挤掉 2348 的锚，把窗口变成两个未验证候选。

> 依据：insights 里已采纳的"两槽提交策略"（锚 + 挑战者，`demystifying_2900` §4.2），
> 以及我们实测的 V1（同版本抽签极差 144）/ V2（跨版本极差 838）——
> **更强的 agent 并不保证更高的分**，所以永远保住一个已证实的高分格。
