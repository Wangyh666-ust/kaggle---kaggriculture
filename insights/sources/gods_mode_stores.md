# God's Mode: Hacked Stores —— 能不能**操纵商店抽取**（leoprovorov）

- **链接**：https://www.kaggle.com/code/leoprovorov/god-s-mode-hacked-stores
- **票数**：本次抓取未见（同作者另有 `a-song-of-ice-and-fire-fixed-flexible`）
- **性质**：**因果推断 + 主动感知 + 对抗控制**的研究性 notebook，不是一份 agent
- **规模自述**：392 场受控对局 / 3,136 次精确核对 / 98 局真实回放 / 31 位种子审计

## 一、机制（与我们已知一致，但我们从未量化到这一步）

> "隐藏的种子决定商店。agent 读不到那个种子，**但它们的农场在每次商店抽取之前消耗同一条随机流**。
> 这个 notebook 分离四个问题：能不能改变一家商店、能不能推断出足够的隐藏状态、
> 能不能请求一家特定的商店、这个干预能不能提高最终分数。"

```
Observe(商店与杂草) -> Infer(候选种子) -> Predict(对手的增量) -> Act(改变空格数) -> Value(挑一家有利的店)
```

### 他的四个回答

| 问题 | 他的答案 |
|---|---|
| 能不能改变下一家商店？ | **能，而且这是测出来的**：一次合法的单格 `DIG` 放在解锁前，**128 次配对干预里 98 次（76.6%）改变了下一家店** |
| 能不能推断隐藏状态？ | 部分。用 10 个"传感器格"维护，**约 34% 的对局**能做出"有信息依据的最后一店决策"，约 **16%** 能接近精确种子 |
| 能不能请求特定商店？ | **有条件**：种子预言机对 `PET_CAFE` 的可达性 **43.8%**，前提是偏移限定在 −3…+3 且仅玩家 0 索引 |
| 最终分数能不能提升？ | **"尚未测量"**（他自己写的）。有向控制在所有对局里的**投影覆盖只有 10–18%** |

### 他自己标注的边界

> "**43.8% 这个结果很强但有条件**…… 目前设计下，覆盖所有对局的投影只有 10–18%……
> 对最终分数的影响：**not measured yet**。"

他还附了两个交互式仪表盘（`field_shops.html`、`shop-dashboard-assets`），一个是**引擎常量模型**下的
TOMATO / PIZZA_SHOP 价格轨迹（含 MILK、WHEAT），"第八次揭示之后游戏还继续六天，这就是为什么
受控的晚店仍然重要"。

## 二、与我们已知的关系

| 我们的结论 | 与他的关系 |
|---|---|
| **E1：同 seed ≠ 同世界**——商店抽取与杂草共用 `(seed×1_000_007)^day` 播种的 RNG，且**杂草只在空格子消耗随机数**，所以商店序列取决于双方打法 | ✅ **他的 76.6% 是这条的强量化版本**：我们只知道"依赖农场地形"，他测出"改一格 = 有 76.6% 概率换掉下一家店" |
| **V1：同版本抽签极差 ≈ 144** | 🔶 可能部分由"我们的布局在变 → 商店序列在变"解释，但**同一份代码在同一批固定种子上是确定的**，所以 144 的极差来自种子本身，不是这条 |
| 我们固定种子的本地 A/B 面板 | ⚠️ **需要注意的混淆**：任何**改变农场地形/空格数**的改动，都会顺带换掉商店序列。所以我们测到的"改动效果"里混着"换了一批商店"的运气。**缓解**：单调剂量-反应（如 V219 三档 435→415→357）不像运气，可采信 |

## 三、状态与待办

| 主张 | 状态 | 说明 |
|---|---|---|
| 单格 DIG 能改变下一家商店（76.6%，n=128） | 🔶 **待我们复核** | 机制与我们 E1 完全兼容，但我们没做过配对干预实验。**本地可复现**（固定 seed、成对跑 `DIG` vs 不 DIG） |
| 有向控制可覆盖 10–18% 的对局 | 🔶 待确认 | 他的设计只对玩家 0 索引，且未在对抗下测 |
| **对最终分数有正影响** | ⚪ **作者本人未测量** | 这是关键缺口：**在没有分数证据前，这不是一条可用的线索** |
| 他的商店/价格仪表盘 | ✅ 可作工具 | 交互式，可以直接用来核对我们 `price_trace` 的商店价格曲线 |

**建议**：这条不该进我们的工程排期，但它给了我们一个**免费的诊断工具**——
我们已有一个"商店序列 vs 农场地形"的探针（`scripts/seed_probe.py`），
把"单格干预"加进去就能**用 20 分钟的本地实验**复核他的 76.6%，并顺手量化
"我们的 A/B 面板里有多少方差来自商店重抽"。这比照搬他的控制策略更值得。
