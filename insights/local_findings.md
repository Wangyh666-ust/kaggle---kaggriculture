## 1. 评分机制（决定一切的前提）

| # | 结论 | 证据 |
|---|---|---|
| R1 | **分数 ≈ 对手平均分 + 300** | 1332→1664、1820→2071、2160→2472、2252→2501（四组，各自 n≥39） |
| R2 | 因此**分数衡量的是"被扔进哪个档位"，不是打得多好** | v37 两轮胜率 **93.8% / 78.1%** 却只有 1664 / 2071；v36 胜率 **65.1%** 却有 2472 |
| R3 | **榜单只有 2 个 active 槽位，取两者较高分** | v27 的 2270.1 在 v28 提交后仍撑着名次；窗口=2（用户截图 + 实测）。⚠️ 我曾从"分数保留"误推为窗口 3–4 |
| R4 | 每个新提交**从低初始分起步**（约 600–1000），涨分取决于对手分 | v25：6 局 1100 → 24 局 1995 → 收敛 2264；v37 首投卡在对手均值 1301 的弱档 |
| R5 | **Elo 非对称**：在 2200 分打 1131 分对手时，赢一局 ≈ 0、**输一局 = 470 局的收益**；1150 打 1131 只有 1.1× | 公式 `Δ=K(S−E)` 直接算；实测 v34 有 **6 次**这种"高分输给远弱对手"（≈60 次期望胜收益），v35 之后消失 |

## 3. 环境与对手场的性质

| # | 结论 | 证据 |
|---|---|---|
| E1 | **同 seed ≠ 同世界**：商店抽取和杂草共用同一台按 `(seed×1_000_003)^day` 播种的 RNG，而杂草只在**空格子**消耗随机数 → **商店序列取决于双方打法**。实测 seed 8823651：头部那局第一家店是 d3 `BAKERY`，我们镜像同 seed 是 `FARMERS_MARKET` | `scripts/seed_probe.py`。**推论：永远无法本地重放头部对局**；固定 seed 的本地 A/B 面板不受影响 |
| E2 | 我们这一档**90% 的对手就是同一份 agent**（65/72 开局签名逐字节相同）；中位边际 **$0**，62% 的局在 ±$1000 内 | `replays_v36` 72 局 |
| E3 | **镜像场里杂草是对称的**（我们 0.21 株/局、对手 0.26；未复用率 94% vs 91%）→ **不是杠杆** | 84 局；相关 r=−0.109 |
| E4 | 我们比 family-2 **少用约 17 格地**（d17 起空 25 格 vs 他们 8 格）、少两条作物线、鹅少一半（3 vs 6），**而雇工数相同（11）** | 我们 189 局 vs family-2 64 局 |
| E5 | 但 **E4 不是可复制的优势**：放宽 V219 填地后，阶段画像确实补上（d23 空格 25→15、番茄格 0→10），**终局收入反而更低** | v39 实验；机制见 [herd_safe_window](sources/herd_safe_window.md) 的 `_CXTB` 价格曲线 |

## 4. 具体机制结论

| # | 结论 | 证据 |
|---|---|---|
| M1 | **早死 bug**（确定性）：step-24 现金 $1 → 付不起 3 个雇工（$1+$1+$2）→ 只雇 1 人 → d1 的 FEED 被 `hand_align` 截断 → 牛饿两天逃逸 → d3 畜群 3（健康 5） | v36 的 62 局里 **5 局（8.1%）**，且**正是最大的 5 场败局**（−$30,092 / −$29,389 / −$24,403 / −$16,601 / −$8,346）。修复 = 开局 20/15→10/5（`V9_OPENING_STEP0`）；本地 step-24 现金中位 **$12 → $18** |
| M2 | **番茄每株恰好产 4 次，与种植日无关**（`max_yield=4` 限的是**产量事件次数**） | 引擎 `_daily_refresh_plants`；所以"提早种"只改销售窗口，不改产量 |
| M3 | **番茄价格在我们局里整季上涨**（d20 $74.5 → d27 $120.2），但**头部局里是平的**（$72→$66）——因为我们这一档几乎没人种番茄 | `scripts/price_trace.py`，24 局 + 15 局 |
| M4 | **V219 番茄层唯一真正卡住的门是"≥3 家吃番茄的店"**（现金门 120/120 全过；price≥70 被 shop≥3 蕴含）；**放宽它是单调亏损** | 触发率 13.3%→30.0%→41.7% ↔ 对手群胜场 **435→415→357**，两块种子同向；机制：3 店 d26-29 卖 80 单位得 $98,396，2 店只有 ~$90–150/单位，而该层成本 ~$11.5k |

## 5. 方法学教训（每一条都用血换过）

| # | 教训 | 代价 |
|---|---|---|
| L1 | **胜率是唯一指标，边际不是**（天梯只记胜负）。边际涨 2.5× 而胜场掉 12/120 是净亏 | v30：+$434→+$1072 但 232/240→211/240 |
| L2 | **"打赢自己上一版"是筛选器，不是验收器**——真镜像里一个 +$62 的微小偏差就能赢 93.7% | v30/v31/v32 三次镜像赢、真实输 |
| L3 | **每臂 ≥500 局，且两个独立种子块方向一致** | `_SR_*` 假阴性（20 局/对手，代价几百 Elo）；ca25 假阳性（块一 58.7% / 块二 39.8%）；毛线店假阳性（被"别的店也晚开"这个对照打掉） |
| L4 | **本地测试台有结构性空洞**：天梯上真正伤我们的 **40.6% 档**，本地没有任何对手能复现 | 意味着**任何本地改动都无法在"有意义的域"被验证** |
| L5 | **镜像对局不保证 $0 平局**：seed 2011 的镜像局是 −$68，重复跑 3 次都是 −$68 → 是**该种子下的座位不对称**，不是随机性 | 曾据此误判"环境座位不对称"，后来用"关掉杂草 40/40 全 $0"纠正 |
| L6 | 同码两次提交可以差 **688 分**（2452.2 vs 1763.7）——所以**单次提交的分数不能当版本证据** | 我们一度据此怀疑"传错文件"；现在有了 V1 的同版本极差 144，才知道 688 属于异常，**仍建议每次提交记录 sha256**（`scripts/submit.py` 已强制） |
